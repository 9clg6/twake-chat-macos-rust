# Decisions

Numbered decisions that change or complete `ARCHITECTURE.md` (section 14). A decision is
merged before the code that needs it. Product decisions of the React app keep their `Dnn`.

## A001 Flat crates, prefix `twake-`
- Context: many small crates with one reason to change, dependency direction checked by machine.
- Decision: one directory per crate under `crates/`, directory name = crate name, all prefixed `twake-`.
- Consequences: `members = ["crates/*", "xtask"]`; extraction of tokens, icons and ui-kit later is a move.
- Risk: more manifests to maintain; mitigated by `[workspace.package]` and `[workspace.lints]`.

## A002 GPUI behind `twake-gpui`
- Context: GPUI is young and its source (crates.io, fork, Zed git) may change.
- Decision: only `twake-gpui` names the GPUI source and re-exports it; everything else imports `twake_gpui`.
- Consequences: swapping the source is a one-line change if the APIs match (spike S1 checks it).
- Risk: the facade leaks GPUI types by design (`pub use gpui::*`); an incompatible fork still means rework.

## A003 Exact-pinned matrix-sdk, one adapter
- Context: matrix-sdk breaks its API often and holds the crypto.
- Decision: `matrix-sdk*` is only in `twake-matrix`, versions pinned with `=`; an upgrade is its own PR.
- Consequences: the rest of the code sees domain types only.
- Risk: slow uptake of security fixes; mitigated by cargo-audit and a dedicated upgrade PR.

## A004 One Tokio runtime, 2 to 4 workers
- Context: GPUI has its own executor; several runtimes waste memory and threads.
- Decision: one multi-thread Tokio runtime built in `twake-desktop`, handed to adapters as a `Handle`; no `#[tokio::main]`, no `full` feature.
- Consequences: `twake-gpui` provides `spawn_io` that aborts the Tokio task when the GPUI task drops.
- Risk: blocking work on the runtime starves sync; blocking work uses `spawn_blocking`.

## A005 Keychain-only secrets
- Context: the session and the store passphrase must not sit in plaintext files.
- Decision: secrets only through the `SecretStore` port, backed by the OS keychain; no plaintext fallback.
- Consequences: with no store available the app fails with a clear error.
- Risk: headless Linux without a Secret Service cannot sign in; spike S3 checks each OS.

## A006 Fluent for i18n (provisional)
- Context: the web app has its own message format with plurals and interpolation.
- Decision: Fluent bundles in `twake-i18n`, to be confirmed after spike S9 (sample of 20 real strings).
- Consequences: a conversion from the web `*.json` files may be needed.
- Risk: format mismatch with the web files; S9 may replace Fluent by generation from the web files.

## A007 Tokens and icons generated and GPUI-free
- Context: the design system lives in `@linagora/twake-mui` and `@linagora/twake-icons`.
- Decision: `twake-tokens` and `twake-icons` are generated by `cargo xtask tokens` / `icons`, no GPUI, no dependency.
- Consequences: generated files are never edited; a token change is a re-export. Until the generators exist, `twake-tokens` holds a hand-written placeholder.
- Risk: drift between export and generator; the version of twake-mui is recorded in the file header.

## A008 Nightly-only E2E
- Context: the React repo runs E2E against a real Synapse every night on `main`, never on a PR.
- Decision: same rule here; PRs run fmt, clippy, tests, deny, audit and build only.
- Consequences: faster PRs; regressions can reach `main` for up to a day.
- Risk: a late failure is harder to attribute; the nightly job reports the commit range.

## A009 Ports return boxed Send futures
- Context: native `async fn` in traits is not dyn-compatible (E0038 on rustc 1.99.1), and the UI holds ports as `Arc<dyn Port + Send + Sync>`.
- Decision: port methods return `Pin<Box<dyn Future + Send>>` (via `#[async_trait]` or an explicit `BoxFuture`).
- Consequences: one allocation per call; fakes and adapters share the same signature.
- Risk: allocation cost on hot paths; measured before any change (principle P7).

## A010 UI starts on gpui 0.2.2, spike S1 does not gate it
- Context: the user asked why S1 blocked UI work; waiting for a spike delays the whole product.
- Decision: UI development starts now on `gpui = "0.2.2"` behind `twake-gpui`. S1 runs in parallel, time-boxed to 2 days, and ends with a decision to stay or migrate.
- Consequences: possible UI rework on migration, bounded by the `twake_gpui` facade (every GPUI import goes through it) and by the GPUI-free crates (tokens, icons, domain, adapters).
- Risk: gpui 0.2.2 has no AccessKit, so the VoiceOver target of section 10 is unreachable on it.

## A011 Dependency check: open questions of the workspace tests
- Context: `xtask check-deps` turns ARCHITECTURE.md section 3 into code; five points of the document were silent.
- Decision: (Q4) `twake-desktop` has no normal dependency on `twake-testing` for now, so `--preview` on fakes waits for a decision. (Q5) `twake-tokens` and `twake-icons` may carry `serde` behind an optional feature; the graph check reads `cargo metadata` without features, so it lets `serde` through on those two and nothing else. (Q6) `twake-domain` and `twake-app` depend on no `tokio*` crate, dev-dependencies included; they use `futures` only. (Q7) Dev-dependencies are not counted against rule 3; they follow the edge table and P2.
- Consequences: ARCHITECTURE.md rule 1 ("`tokio::sync` types") is stricter in the check than in the text; the text is read as superseded by this note.
- Risk: a core crate that needs `tokio::sync` must change this decision first.
