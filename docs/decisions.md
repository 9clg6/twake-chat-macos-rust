# Decisions

Numbered decisions that change or complete `ARCHITECTURE.md` (section 14). A decision is
merged before the code that needs it. Product decisions of the React app keep their `Dnn`.

## A001 Flat crates, prefix `twake-`
- Context: many small crates with one reason to change, dependency direction checked by machine.
- Decision: one directory per crate under `crates/`, directory name = crate name, all prefixed `twake-`.
- Consequences: `members = ["crates/*", "xtask"]`; extraction of tokens, icons and ui-kit later is a move.
- Risk: more manifests to maintain; mitigated by `[workspace.package]` and `[workspace.lints]`.

## A002 GPUI behind `twake-gpui`
- Context: GPUI is young and its source (crates.io, fork, Zed git) may change.
- Decision: only `twake-gpui` names the GPUI source and re-exports it; everything else imports `twake_gpui`.
- Consequences: swapping the source is a one-line change if the APIs match (spike S1 checks it).
- Risk: the facade leaks GPUI types by design (`pub use gpui::*`); an incompatible fork still means rework.

## A003 Exact-pinned matrix-sdk, one adapter
- Context: matrix-sdk breaks its API often and holds the crypto.
- Decision: `matrix-sdk*` is only in `twake-matrix`, versions pinned with `=`; an upgrade is its own PR.
- Consequences: the rest of the code sees domain types only.
- Risk: slow uptake of security fixes; mitigated by cargo-audit and a dedicated upgrade PR.

## A004 One Tokio runtime, 2 to 4 workers
- Context: GPUI has its own executor; several runtimes waste memory and threads.
- Decision: one multi-thread Tokio runtime built in `twake-desktop`, handed to adapters as a `Handle`; no `#[tokio::main]`, no `full` feature.
- Consequences: `twake-gpui` provides `spawn_io` that aborts the Tokio task when the GPUI task drops.
- Risk: blocking work on the runtime starves sync; blocking work uses `spawn_blocking`.

## A005 Keychain-only secrets
- Context: the session and the store passphrase must not sit in plaintext files.
- Decision: secrets only through the `SecretStore` port, backed by the OS keychain; no plaintext fallback.
- Consequences: with no store available the app fails with a clear error.
- Risk: headless Linux without a Secret Service cannot sign in; spike S3 checks each OS.

## A006 Fluent for i18n (provisional)
- Context: the web app has its own message format with plurals and interpolation.
- Decision: Fluent bundles in `twake-i18n`, to be confirmed after spike S9 (sample of 20 real strings).
- Consequences: a conversion from the web `*.json` files may be needed.
- Risk: format mismatch with the web files; S9 may replace Fluent by generation from the web files.

## A007 Tokens and icons generated and GPUI-free
- Context: the design system lives in `@linagora/twake-mui` and `@linagora/twake-icons`.
- Decision: `twake-tokens` and `twake-icons` are generated by `cargo xtask tokens` / `icons`, no GPUI, no dependency.
- Consequences: generated files are never edited; a token change is a re-export. Until the generators exist, `twake-tokens` holds a hand-written placeholder.
- Risk: drift between export and generator; the version of twake-mui is recorded in the file header.

## A008 Nightly-only E2E
- Context: the React repo runs E2E against a real Synapse every night on `main`, never on a PR.
- Decision: same rule here; PRs run fmt, clippy, tests, deny, audit and build only.
- Consequences: faster PRs; regressions can reach `main` for up to a day.
- Risk: a late failure is harder to attribute; the nightly job reports the commit range.

## A009 Ports return boxed Send futures
- Context: native `async fn` in traits is not dyn-compatible (E0038 on rustc 1.99.1), and the UI holds ports as `Arc<dyn Port + Send + Sync>`.
- Decision: port methods return `Pin<Box<dyn Future + Send>>` (via `#[async_trait]` or an explicit `BoxFuture`).
- Consequences: one allocation per call; fakes and adapters share the same signature.
- Risk: allocation cost on hot paths; measured before any change (principle P7).

## A010 UI starts on gpui 0.2.2, spike S1 does not gate it
- Context: the user asked why S1 blocked UI work; waiting for a spike delays the whole product.
- Decision: UI development starts now on `gpui = "0.2.2"` behind `twake-gpui`. S1 runs in parallel, time-boxed to 2 days, and ends with a decision to stay or migrate.
- Consequences: possible UI rework on migration, bounded by the `twake_gpui` facade (every GPUI import goes through it) and by the GPUI-free crates (tokens, icons, domain, adapters).
- Risk: gpui 0.2.2 has no AccessKit, so the VoiceOver target of section 10 is unreachable on it.

## A011 Dependency check: open questions of the workspace tests
- Context: `xtask check-deps` turns ARCHITECTURE.md section 3 into code; five points of the document were silent.
- Decision: (Q4) `twake-desktop` has no normal dependency on `twake-testing` for now, so `--preview` on fakes waits for a decision. (Q5) `twake-tokens` and `twake-icons` may carry `serde` behind an optional feature; the graph check reads `cargo metadata` without features, so it lets `serde` through on those two and nothing else. (Q6) `twake-domain` and `twake-app` depend on no `tokio*` crate, dev-dependencies included; they use `futures` only. (Q7) Dev-dependencies are not counted against rule 3; they follow the edge table and P2.
- Consequences: ARCHITECTURE.md rule 1 ("`tokio::sync` types") is stricter in the check than in the text; the text is read as superseded by this note.
- Risk: a core crate that needs `tokio::sync` must change this decision first.

## A012 Token generator: dependencies and spellings
- Context: `cargo xtask tokens` turns `docs/spec/tokens.json` into `twake-tokens/src/generated.rs`; the tests were written before the code.
- Decision: `serde_json` is a dev-dependency of `twake-tokens` (its tests read `tokens.json`; dev-dependencies do not count against rule 3, A011 Q7) and a normal dependency of `xtask` (a build tool, not a product crate). A shade is read with `PRIMARY.shade(600)`, not `PRIMARY[600]` (a lookup that can fail, `None` for any other number). The command takes `--input FILE` and `--output FILE` besides `--check`, for tests and for other token files.
- Scope: not generated first: shadows, zIndex, transitions, the accents of Grey, components and icons (all in `tokens.json`). A026 lifted it for the shadows (`tokens.json` and `generated.rs` carry them), zIndex, transitions and `action`; the accents of Grey, components and icons stay out.
- Consequences: `twake-tokens` stays dependency-free; `generated.rs` is committed and CI runs `cargo xtask tokens --check`; the placeholder `THEME` is gone, `twake-desktop` reads `LIGHT`.
- Risk: none beyond a stale `generated.rs`, which `--check` catches.

## A013 Icon generator: schema, names and limits
- Context: `cargo xtask icons` turns `docs/spec/icons.json` (the SVG sprite of `@linagora/twake-icons@3.0.0`, exported by `docs/spec/export-icons.mjs`) into `twake-icons/src/generated.rs`; the tests were written before the code.
- Decision: the input is `{"source": "<package>@<version>", "icons": {"<id>": {"viewBox": "<min-x min-y width height>", "body": "<svg elements>"}}}`. Ids are kebab-case (`carbonCopy` of the package became `carbon-copy` in the export); a viewBox is four numbers, spaces and/or commas, width and height above zero. `assign-admin` and `assign-moderator` have no viewBox in the package and got `0 0 16 16`, the default size of its `Icon`. The 34 icons that used the shared `<defs>` carry their own copy, with the ids prefixed `<icon>-`, so every body stands alone. A constant is the id in screaming snake case, prefixed `I_` when it starts with a digit or is `ALL` (`3d-rotate` is `I_3D_ROTATE`); two ids with one name are refused. The body is an escaped string literal (`\`, `"`, newline), never a raw string. `ALL` is sorted by id, so `by_id` is a binary search. The `--input`, `--output` and `--check` flags and the exit codes (0, 1 stale, 2 failure) are those of `tokens`, in one shared code path. `generated.rs` is written without trailing commas, so `#[rustfmt::skip]` is on its `mod`; it has `///` docs, so no `missing_docs` suppression.
- Scope: icons whose colours are hard-coded in the package (reported by the exporter) keep them: they do not follow `currentColor` and cannot be recoloured.
- Consequences: `generated.rs` is committed and CI runs `cargo xtask icons --check`; `twake-icons` stays dependency-free.
- Risk: none beyond a stale `generated.rs`, which `--check` catches; a bad id or viewBox in a new export fails the generator.

## A014 Button: `action` colours in twake-ui-kit, pressed, paddings, ring
- Context: `twake-tokens` had no `action` colours at first; the ui-kit foundation tests (`crates/twake-ui-kit/tests`) pin the values of design-system.md lines 107-114.
- Decision: the `action` colours (hover, disabled, disabledBackground, focus) come from `twake-tokens` (A026); `twake-ui-kit::button` holds no constant of them any more. Pressed looks like hover (MUI has no pressed colour). Outlined small and large padding are deduced (16 x 9, 32 x 13). The focus ring is 2 px in `primary.main`. The colour glue is `twake_ui_kit::color`, not `twake-gpui`, so the edge `twake-gpui -> twake-tokens` stays forbidden (`check-deps`).
- Consequences: `Button` in `view.rs` has no test (needs a window).
- Risk: the deduced paddings may differ from twake-mui; the disabled outlined border is not decided (it follows the text colour).

## A015 Accent folding in `twake-domain`: `unicode-normalization`
- Context: the search of a room name ignores case and accents (D392, `room_list::matches_search`); the standard library has no accent folding.
- Decision: `twake-domain` depends on `unicode-normalization` (pure Rust, no tokio, no I/O). A name and a query are folded the same way: NFD, combining marks removed, then lower case.
- Consequences: "Élodie" is found by "elo" and "ÉLO"; letters that do not decompose (`ø`, `ß`, `æ`) are not folded. `cargo xtask check-deps` accepts the dependency (rule 1 forbids adapters, GPUI and `tokio*` only).
- Risk: a new Unicode version may change a decomposition; the tests pin a few accents only.

## A016 Fluent for the UI texts: `fluent-bundle`, keys, bundled catalogues
- Context: the room row and the bubble need texts in the language of the reader (A006); the tests were written with fixture catalogues.
- Decision: `twake-i18n` uses `fluent-bundle` 0.16 (concurrent bundle, so `Locale` is `Send + Sync`) and `unic-langid`; plurals come from `intl_pluralrules` inside `fluent-bundle`. `fluent-templates` was not taken: it loads catalogues from a directory at build time through macros and pulls more crates, while here a catalogue is one string. `use_isolating(false)`: no Unicode marks around arguments. An unknown key gives the key; a bad catalogue entry is skipped; a bad language tag falls back to the undetermined one. The real catalogues are `crates/twake-i18n/locales/{en,fr}.ftl` (embedded with `include_str!`), keys named in `docs/dev/ui-screens-api-sketch.md` section 1; `Locale::bundled(lang, utc_offset_secs)` picks `fr*`, else English. Licences MIT/Apache-2.0, pure Rust, no `tokio`; `cargo xtask check-deps` accepts them.
- Product choices the specs left open: runs of messages group within 5 minutes (`GROUP_GAP_MS`); "this week" is a rolling six days before today; the 12 hour clock is supported (`HourCycle`); a read receipt on an event not in the list, and a reply whose target is not loaded, are out of scope (no read mark, no quote).
- Consequences: a locale detected from the OS and the web `*.json` conversion (S9) come later; the key list is the one of the sketch only.
- Risk: the web strings may need ICU features Fluent lacks (S9); the grapheme cut of the avatar initials is approximate (combining marks and joiners, no UAX 29 crate).

## A017 Sign-in core: `url`, `serde_json`, and the open points of the sketch
- Context: the pure part of sign-in (`docs/dev/signin-api-sketch.md`) parses addresses and JSON bodies and builds the SSO URL; the tests were written before the code.
- Decision: `twake-domain` depends on `url` 2 and `serde_json` 1, `twake-app` on `url` 2 (pure Rust, no tokio, no I/O; `cargo xtask check-deps` accepts them; JSON is read from `&str`, no serde type crosses the API). `Secret` does not zeroize on drop (no `zeroize` dependency; no test can observe it). Points left open by the sketch: (Q5) `serves_directly` compares `host[:port]` whole and case-sensitively, so an explicit `:443` or an upper-case host is another server name (`false` is the safe answer: the caller then reads the well-known); (Q6) provider ids match `[A-Za-z0-9._~-]+`, not `.` or `..`; (Q7) the randomness of an SSO attempt is a `[u8; 16]` given by the caller; device id after `SignOut` of an `Expired` session or `SignOutDone` is forgotten, after a 401 it is kept; a 401 while a stored session is checked (`Restore`) is reported as `LoginFailed` and leads to `AwaitingLogin`.
- Consequences: a stored session the server refuses asks for a new sign-in without an "expired" message; the SSO URL builds the identity provider segment with `path_segments_mut`, so a hand-made `IdentityProvider` cannot escape the path.
- Risk: a future `url` major version changes parsing details; the tests pin the normal form.
- Open points: `Secret` is not zeroized (follow-up with the keychain adapter, `zeroize` in `twake-store`/`twake-domain`); `accept_callback` returns a bare `Secret`, so the adapter must apply `claimLoginToken`/`servesUser` of the React app before `Active`; the loopback listener gives a relative path, the adapter rebuilds the URL with the received `Host` header, not its listen address; the React app forgets the device id on sign-out unless the server ended the session (`session.tsx` `keepDevice`): A017 matches.

## A018 `cargo deny`: ignores by advisory id, reviewed at each gpui bump
- Context: `cargo deny check` failed on 11 "unmaintained" advisories, all transitive through `gpui` 0.2.2 (`gpui_http_client`, `gpui_util`, `metal`, `cosmic-text`, `usvg`, `stacksafe`, `ashpd`/`oo7`/`zbus`); on 12 wildcard bans (`path` dependencies between workspace crates); on the missing `license` field of the 17 workspace crates; and on `libfuzzer-sys` (`(MIT OR Apache-2.0) AND NCSA`, via gpui -> image -> ravif -> rav1e).
- Decision: `[bans] allow-wildcard-paths = true`; `[licenses.private] ignore = true` (the crates are `publish = false` through `workspace.package`; no licence is chosen here); `[advisories] ignore` lists each unmaintained advisory by id with its dependency chain and review date. `unmaintained` is not turned off, no vulnerability is ignored, `duplicate` versions stay warnings. NCSA (permissive) is allowed for `libfuzzer-sys` alone, as a `licenses.exceptions` entry. `cargo deny check` runs once in CI, on Ubuntu.
- Consequences: a new advisory fails the build until it is read and either fixed or listed with a reason; entries whose crate leaves the graph are reported as unused.
- Review: at each gpui bump, remove the ignores that no longer apply and re-read the rest.

## A019 matrix-sdk 0.19.1 features and TLS provider (spike S2)
- Context: spike S2 (`docs/dev/matrix-sdk-spike.md`) built `twake-matrix` with `matrix-sdk` and `matrix-sdk-ui` 0.19.1. The SDK has one rustls feature, `rustls-aws-lc-rs`; `gpui` brings `ring` into the desktop binary.
- Decision: features `e2e-encryption`, `automatic-room-key-forwarding`, `sqlite`, `rustls-aws-lc-rs`, default features off; sliding sync needs no feature. The composition root installs the aws-lc-rs provider once at start-up. The store takes the keychain secret as a raw key (`SqliteStoreConfig::key`), not a passphrase. Crates holding SDK futures set `recursion_limit = "256"`. `deny.toml` ignores RUSTSEC-2026-0319 (`anymap2`, unmaintained, via matrix-sdk).
- Consequences: no OpenSSL or native-tls in the graph. Open and not decided here: RUSTSEC-2026-0459 (`libsqlite3-sys` 0.38.2, vulnerability, bundled SQLite only; the macOS build links the system library) and the `CDLA-Permissive-2.0` licence line.
- Review: at each matrix-sdk bump, check that `matrix-sdk-sqlite` uses rusqlite >= 0.41 and drop the ignore if `anymap2` is gone.

## A020 Composer Markdown: our own bounded parser, no crate; allowed link schemes
- Context: the composer sends Chat Markdown as `org.matrix.custom.html` (D35, FR-052..FR-054; tests in `crates/twake-domain/tests/{markdown,mention,commands}.rs`, API in `docs/dev/composer-api-sketch.md`). A full CommonMark crate (`pulldown-cmark`) would pass raw HTML through, read headings, images, tables and nested blocks the chat never sends, and add a dependency for a subset of eight marks.
- Decision: `twake_domain::markdown` is a small parser of our own, no new dependency (`cargo xtask check-deps` and `cargo deny check` unchanged). It works line by line: a block pass (fenced code, `> ` quote, `- `/`* ` and `1. `/`1) ` lists, text lines joined by `<br>`) and an inline pass (`**` `*` `_` `~~` `<u>` `` ` `` `[t](url)`), recursive inside a mark except code. Every character that is not a mark is escaped (`& < > " '`) before it reaches the HTML, so a tag typed by the user never comes out; the proptests strip the tags built here and expect no `<` left. All slicing is on `char` boundaries (`char_indices`, `strip_prefix`, `floor_char_boundary`), never on a byte offset taken from a width guess, so a multi-byte space (U+0085, U+00A0) cannot cut a string.
- Links: only `http://`, `https://`, `mailto:` and `matrix:` become `<a href>` (case ignored, no whitespace or control character, something after the scheme); any other `[t](url)` stays text. The href is escaped. The link dialog (`link_markdown`, D97) is stricter: `http(s)://` and `www.` only, as the sketch says; it percent-encodes `(` and `)` of the address so that they cannot end the link early. `matrix:` is not in the sketch: added on request of the owner of the slice, for links to Matrix entities.
- Limits: no nested lists or quotes, no headings, images, tables or autolinks; a backslash escapes one of `\ * _ [ ] ( ) < ~ ` # > -` (the text after it is literal), anything else after a backslash stays as typed (a bare `www.x.org` is left to the display); a mark needs a non-space inside both edges; `*i*` and `_i_` are not read inside a word or as part of a doubled mark; the language word after an opening fence (` ```rust `) is accepted and dropped; an unclosed fence stays text; a text with no Markdown has `formatted_body: None` (the HTML would be the escaped text with `<br>`).
- Other choices of the slice: a text of spaces and newlines alone shows the microphone, as an empty one; after Escape the suggestions stay closed while the trigger (kind, start, query) is unchanged and open again as soon as it changes; the lists stop at 25 people (`MAX_MENTIONS`, FR-054) but `extract` does not: every person picked and still named is mentioned, `@room` comes in addition; a replied author is added to `mentions` and `notify` as well; `ComposerState::new` takes the room for the API of the sketch but does not keep it (the screen pairs the composer with the room whose draft it saves); an accepted emoji is written without a trailing space.
- Names stay literal: the name written for a mention is stored with its Markdown escaped by `escape_markdown` (backslash before `* [ ] _ < ~ \` \`, and before a leading `>` or `-`), so `**x**` or `[x](https://evil.example)` as a display name is text, not a mark. The plain `body` sent holds the raw name (no backslash; `unescape_names`), `formatted_body` the matrix.to link. An edit loads the old body with its names escaped again. A link address ends at the first `)`; one with a `(`, a space or a control char is no link, which also keeps the link scan linear (64 KiB of `[` took 2.25 s, now 0.01 s, debug).
- Gaps to confirm with the owner (Matrix spec, D418): (1) href schemes are `http`, `https`, `mailto`, `matrix`; the React client accepts `http(s)` and `mailto:` only: a deliberate difference, to confirm. (2) The React drafts are kept per account and wiped when an account signs out; `DraftStorePort` here is keyed by `RoomId` alone (`save`, `load`, `clear` of one room), so it cannot wipe by account: gap, to fix when the store gets its account key. (3) Code blocks come out as `<pre><code>` without a `class="language-*"`, as in the React client; the language word is dropped.
- Consequences: the subset is pinned by the tests of the three files and two proptests; a new mark is a new function in `markdown/inline.rs` and a test first.
- Risk: homemade parsing misreads edge cases CommonMark would read otherwise (`*a **b** c*` works, `***x***` gives nested marks by luck of order); the escaping, not the parser, carries the safety, and the proptests check it.

## A021 Text buffer in `twake-ui-kit`; `unicode-segmentation` as a normal dependency
- Context: the composer field needs a model of text, cursor, selection, words, undo and IME composition (`docs/dev/text-input-api-sketch.md`; 158 tests in `crates/twake-ui-kit/tests/text_buffer_*.rs`, written before the code). GPUI 0.2.2 has no text field to reuse; the model has no window, so it can be tested alone.
- Decision: `twake_ui_kit::text_buffer` (GPUI-free, like `theme` and `color`), not `twake-domain` (its allow list has no segmentation crate and no other layer reads a cursor). It depends on `unicode-segmentation` 1 (UAX 29 clusters and words; MIT OR Apache-2.0; already in `Cargo.lock` through GPUI, so `cargo deny` and `cargo xtask check-deps` need no new ignore or edge). `max_len` counts Unicode scalar values; `set_marked_text` puts the cursor at the end of the marked text (the `selectedRange` of macOS is ignored); a triple click selects the line with its trailing `\n`; an insertion that is empty once cleaned changes nothing (`set_text("")` still clears: it is how the field is emptied after a send); Emacs keys (Ctrl+K, Ctrl+A, Ctrl+E) are out of scope. History stores edits (position, removed, inserted), never snapshots.
- Consequences: word moves and the column of Up/Down scan the whole text (linear, fine for a composer; a 10 000-character text is still instant); the view converts positions with `utf8_range_to_utf16` for the OS.
- Risk: an IME that moves the caret inside its clause (Japanese) is not followed until `set_marked_text` takes a third argument; word rules treat emoji as separators.

## A022 GPUI source: migrate to `gpui-unofficial` =1.28.1 (spike S1) - proposed
- Status: proposed, not accepted; the owner decides. Nothing in `main` changes until then.
- Context: spike S1 (`docs/dev/gpui-source-spike.md`). crates.io `gpui` 0.2.2 (2025-10-22) has no accessibility; Zed `main` has AccessKit since 2026-05-27 (#56065) on macOS, Windows and Linux. Zed git as a direct dependency does not resolve here (cargo picks another package named `gpui`); `gpui-unofficial` 1.28.1 repackages Zed tag `v1.28.1` (`e8bc16a`) on crates.io.
- Proposal: `twake-gpui` depends on `gpui = { package = "gpui-unofficial", version = "=1.28.1" }` and `gpui_platform = { package = "gpui-platform-gpui-unofficial", version = "=1.28.1" }`. Measured: it builds with 6 changed lines (`ViewElement`, `BoxShadow::inset`, `Window::focus(cx)`, `gpui_platform::application()`), `--preview` starts, `cargo deny` ok with 6 A018 ignores unused, release binary 9.5 MB against 6.4 MB, cold build 1m23 against 1m50, one clean bench run equal to the baseline.
- Alternatives: stay on 0.2.2 (no a11y; own NSAccessibility or AccessKit layer later, weeks of work per platform); hybrid with two dependency sets (rejected, APIs differ); `gpui-ce` (divergent surface).
- Risks: a repackager who is not Zed (trust and continuity not verified); pre-1.0 breaking changes; open upstream a11y bugs (#66691 focus, #66690 cached views, #65623 duplicate ids); VoiceOver not yet tried; bench noisy.
- To do before accepting: items of section 5 of the spike, first the VoiceOver pass and a calm bench.

## A024 Settings core: pure preferences, notification levels, one port - deviations to validate
- Context: FR-128, FR-129, FR-133 (`docs/dev/settings-api-sketch.md`; tests in `crates/twake-domain/tests/{preferences,preferences_json,notification_level}.rs`, `crates/twake-app/tests/settings_state.rs`, `crates/twake-testing/tests/preferences_store.rs`).
- Decision: `twake_domain::{preferences, notifications}` and `twake_app::settings` are pure (A011); `PreferencesPort` (boxed `Send` futures, A009) has `FakePreferences` and a contract suite for the future `twake-store` adapter. No new dependency (`serde_json` was already in `twake-domain`; `cargo xtask check-deps` and `cargo deny check` pass).
- The owner's rule is to follow the React client. Resolved: (1) `All` is firm for a room, as in React (a room on `All` notifies whatever the account default); (2) a muted room is `None` only; (3) two account levels, `direct_messages` and `groups` (`All` or `Mentions`), picked per `RoomKind` by `effective_level(room, kind, defaults)`, as in React; (4) the theme AND the language of the common settings of ToM win over the local choice while they are set (D38, D67): `ViewSettings.appearance_locked`, `language_locked`, `common_settings_url`; the local choice is never touched and comes back; the language is the first two letters of ToM's value (`fra` is `fr`), as in React; (5) JSON v2: the former `notifications` key is read only when `direct_messages` and `groups` are absent, an invalid value is the default of its field.
- Still open, to be validated by the owner:

## A027 Matrix session adapter and keychain store: store key, one entry, login errors, sign-out
- Context: `twake-matrix` (`build_client`, `login_with_token`, `restore_session`, `sign_out`, `expiry`) and `twake-store` (`KeychainSessionStore`) of the branch `feat/matrix-session`; tests in `crates/twake-matrix/tests/{login,restore,sign_out,client}.rs` and `crates/twake-store/tests/keychain_session_store.rs`.
- Decision:
  1. The key of the SQLite store is 64 hexadecimal characters (32 bytes), per account.
  2. The keychain holds one entry, `sessions`, with one line per session (`user device homeserver token`); one entry keeps the order of the accounts and makes each change atomic. `save` refuses, before writing, a token that is empty or holds whitespace (Unicode included) or a control character: `SessionStoreError::Unavailable`, the saved sessions untouched.
  3. `restore_session` refuses a session whose homeserver is not the one of the client: `RestoreError::WrongHomeserver`.
  4. Login errors: a refused token (a Matrix error kind) is `InvalidToken`; a 5xx, a rate limit, a 4xx without a Matrix body and any other answer is `Server`; only a transport failure (no HTTP status, e.g. closed port) is `Unreachable`.
  5. `sign_out(client, root, user)` derives the folder itself, `account_data_dir(root, user)`, and removes only that; a symbolic link in its place is removed, never followed. The server is asked once; the local data goes even if it cannot answer.
- Still open:
  1. Maximum size of a Windows Credential Manager entry against 5 sessions in one entry.
  2. Deleting the store folder while a client is still open is not checked on Windows.
  3. The real keychain adapter is spike S3; only the `Keychain` trait and a memory fake exist.
- Consequences: a caller never passes a path to `sign_out`; the keychain entry is cleared by the caller through `SessionStorePort`.
