# Decisions

Numbered decisions that change or complete `ARCHITECTURE.md` (section 14). A decision is
merged before the code that needs it. Product decisions of the React app keep their `Dnn`.

## A001 Flat crates, prefix `twake-`
- Context: many small crates with one reason to change, dependency direction checked by machine.
- Decision: one directory per crate under `crates/`, directory name = crate name, all prefixed `twake-`.
- Consequences: `members = ["crates/*", "xtask"]`; extraction of tokens, icons and ui-kit later is a move.
- Risk: more manifests to maintain; mitigated by `[workspace.package]` and `[workspace.lints]`.

## A002 GPUI behind `twake-gpui`
- Context: GPUI is young and its source (crates.io, fork, Zed git) may change.
- Decision: only `twake-gpui` names the GPUI source and re-exports it; everything else imports `twake_gpui`.
- Consequences: swapping the source is a one-line change if the APIs match (spike S1 checks it).
- Risk: the facade leaks GPUI types by design (`pub use gpui::*`); an incompatible fork still means rework.

## A003 Exact-pinned matrix-sdk, one adapter
- Context: matrix-sdk breaks its API often and holds the crypto.
- Decision: `matrix-sdk*` is only in `twake-matrix`, versions pinned with `=`; an upgrade is its own PR.
- Consequences: the rest of the code sees domain types only.
- Risk: slow uptake of security fixes; mitigated by cargo-audit and a dedicated upgrade PR.

## A004 One Tokio runtime, 2 to 4 workers
- Context: GPUI has its own executor; several runtimes waste memory and threads.
- Decision: one multi-thread Tokio runtime built in `twake-desktop`, handed to adapters as a `Handle`; no `#[tokio::main]`, no `full` feature.
- Consequences: `twake-gpui` provides `spawn_io` that aborts the Tokio task when the GPUI task drops.
- Risk: blocking work on the runtime starves sync; blocking work uses `spawn_blocking`.

## A005 Keychain-only secrets
- Context: the session and the store passphrase must not sit in plaintext files.
- Decision: secrets only through the `SecretStore` port, backed by the OS keychain; no plaintext fallback.
- Consequences: with no store available the app fails with a clear error.
- Risk: headless Linux without a Secret Service cannot sign in; spike S3 checks each OS.

## A006 Fluent for i18n (provisional)
- Context: the web app has its own message format with plurals and interpolation.
- Decision: Fluent bundles in `twake-i18n`, to be confirmed after spike S9 (sample of 20 real strings).
- Consequences: a conversion from the web `*.json` files may be needed.
- Risk: format mismatch with the web files; S9 may replace Fluent by generation from the web files.

## A007 Tokens and icons generated and GPUI-free
- Context: the design system lives in `@linagora/twake-mui` and `@linagora/twake-icons`.
- Decision: `twake-tokens` and `twake-icons` are generated by `cargo xtask tokens` / `icons`, no GPUI, no dependency.
- Consequences: generated files are never edited; a token change is a re-export. Until the generators exist, `twake-tokens` holds a hand-written placeholder.
- Risk: drift between export and generator; the version of twake-mui is recorded in the file header.

## A008 Nightly-only E2E
- Context: the React repo runs E2E against a real Synapse every night on `main`, never on a PR.
- Decision: same rule here; PRs run fmt, clippy, tests, deny, audit and build only.
- Consequences: faster PRs; regressions can reach `main` for up to a day.
- Risk: a late failure is harder to attribute; the nightly job reports the commit range.

## A009 Ports return boxed Send futures
- Context: native `async fn` in traits is not dyn-compatible (E0038 on rustc 1.99.1), and the UI holds ports as `Arc<dyn Port + Send + Sync>`.
- Decision: port methods return `Pin<Box<dyn Future + Send>>` (via `#[async_trait]` or an explicit `BoxFuture`).
- Consequences: one allocation per call; fakes and adapters share the same signature.
- Risk: allocation cost on hot paths; measured before any change (principle P7).

## A010 UI starts on gpui 0.2.2, spike S1 does not gate it
- Context: the user asked why S1 blocked UI work; waiting for a spike delays the whole product.
- Decision: UI development starts now on `gpui = "0.2.2"` behind `twake-gpui`. S1 runs in parallel, time-boxed to 2 days, and ends with a decision to stay or migrate.
- Consequences: possible UI rework on migration, bounded by the `twake_gpui` facade (every GPUI import goes through it) and by the GPUI-free crates (tokens, icons, domain, adapters).
- Risk: gpui 0.2.2 has no AccessKit, so the VoiceOver target of section 10 is unreachable on it.

## A011 Dependency check: open questions of the workspace tests
- Context: `xtask check-deps` turns ARCHITECTURE.md section 3 into code; five points of the document were silent.
- Decision: (Q4) `twake-desktop` has no normal dependency on `twake-testing` for now, so `--preview` on fakes waits for a decision. (Q5) `twake-tokens` and `twake-icons` may carry `serde` behind an optional feature; the graph check reads `cargo metadata` without features, so it lets `serde` through on those two and nothing else. (Q6) `twake-domain` and `twake-app` depend on no `tokio*` crate, dev-dependencies included; they use `futures` only. (Q7) Dev-dependencies are not counted against rule 3; they follow the edge table and P2.
- Consequences: ARCHITECTURE.md rule 1 ("`tokio::sync` types") is stricter in the check than in the text; the text is read as superseded by this note.
- Risk: a core crate that needs `tokio::sync` must change this decision first.

## A012 Token generator: dependencies and spellings
- Context: `cargo xtask tokens` turns `docs/spec/tokens.json` into `twake-tokens/src/generated.rs`; the tests were written before the code.
- Decision: `serde_json` is a dev-dependency of `twake-tokens` (its tests read `tokens.json`; dev-dependencies do not count against rule 3, A011 Q7) and a normal dependency of `xtask` (a build tool, not a product crate). A shade is read with `PRIMARY.shade(600)`, not `PRIMARY[600]` (a lookup that can fail, `None` for any other number). The command takes `--input FILE` and `--output FILE` besides `--check`, for tests and for other token files.
- Scope: not generated for now: shadows, zIndex, transitions, the accents of Grey, components and icons (all in `tokens.json`); the 1:1 copy of twake-mui will need them later.
- Consequences: `twake-tokens` stays dependency-free; `generated.rs` is committed and CI runs `cargo xtask tokens --check`; the placeholder `THEME` is gone, `twake-desktop` reads `LIGHT`.
- Risk: none beyond a stale `generated.rs`, which `--check` catches.

## A013 Icon generator: schema, names and limits
- Context: `cargo xtask icons` turns `docs/spec/icons.json` (the SVG sprite of `@linagora/twake-icons@3.0.0`, exported by `docs/spec/export-icons.mjs`) into `twake-icons/src/generated.rs`; the tests were written before the code.
- Decision: the input is `{"source": "<package>@<version>", "icons": {"<id>": {"viewBox": "<min-x min-y width height>", "body": "<svg elements>"}}}`. Ids are kebab-case (`carbonCopy` of the package became `carbon-copy` in the export); a viewBox is four numbers, spaces and/or commas, width and height above zero. `assign-admin` and `assign-moderator` have no viewBox in the package and got `0 0 16 16`, the default size of its `Icon`. The 34 icons that used the shared `<defs>` carry their own copy, with the ids prefixed `<icon>-`, so every body stands alone. A constant is the id in screaming snake case, prefixed `I_` when it starts with a digit or is `ALL` (`3d-rotate` is `I_3D_ROTATE`); two ids with one name are refused. The body is an escaped string literal (`\`, `"`, newline), never a raw string. `ALL` is sorted by id, so `by_id` is a binary search. The `--input`, `--output` and `--check` flags and the exit codes (0, 1 stale, 2 failure) are those of `tokens`, in one shared code path. `generated.rs` is written without trailing commas, so `#[rustfmt::skip]` is on its `mod`; it has `///` docs, so no `missing_docs` suppression.
- Scope: icons whose colours are hard-coded in the package (reported by the exporter) keep them: they do not follow `currentColor` and cannot be recoloured.
- Consequences: `generated.rs` is committed and CI runs `cargo xtask icons --check`; `twake-icons` stays dependency-free.
- Risk: none beyond a stale `generated.rs`, which `--check` catches; a bad id or viewBox in a new export fails the generator.

## A014 Button: `action` colours in twake-ui-kit, pressed, paddings, ring
- Context: `twake-tokens` has no `action` colours; the ui-kit foundation tests (`crates/twake-ui-kit/tests`) pin the values of design-system.md lines 107-114.
- Decision: hover alpha (10 light, 20 dark), disabled (61, 82) and disabledBackground (31) are constants of `twake-ui-kit::button`, until the token generator exports `action`. Pressed looks like hover (MUI has no pressed colour). Outlined small and large padding are deduced (16 x 9, 32 x 13). The focus ring is 2 px in `primary.main`. The colour glue is `twake_ui_kit::color`, not `twake-gpui`, so the edge `twake-gpui -> twake-tokens` stays forbidden (`check-deps`).
- Consequences: the constants move to `twake-tokens` when `action` is generated; `Button` in `view.rs` has no test (needs a window).
- Risk: the deduced paddings may differ from twake-mui; the disabled outlined border is not decided (it follows the text colour).

## A015 Accent folding in `twake-domain`: `unicode-normalization`
- Context: the search of a room name ignores case and accents (D392, `room_list::matches_search`); the standard library has no accent folding.
- Decision: `twake-domain` depends on `unicode-normalization` (pure Rust, no tokio, no I/O). A name and a query are folded the same way: NFD, combining marks removed, then lower case.
- Consequences: "Élodie" is found by "elo" and "ÉLO"; letters that do not decompose (`ø`, `ß`, `æ`) are not folded. `cargo xtask check-deps` accepts the dependency (rule 1 forbids adapters, GPUI and `tokio*` only).
- Risk: a new Unicode version may change a decomposition; the tests pin a few accents only.

## A016 Fluent for the UI texts: `fluent-bundle`, keys, bundled catalogues
- Context: the room row and the bubble need texts in the language of the reader (A006); the tests were written with fixture catalogues.
- Decision: `twake-i18n` uses `fluent-bundle` 0.16 (concurrent bundle, so `Locale` is `Send + Sync`) and `unic-langid`; plurals come from `intl_pluralrules` inside `fluent-bundle`. `fluent-templates` was not taken: it loads catalogues from a directory at build time through macros and pulls more crates, while here a catalogue is one string. `use_isolating(false)`: no Unicode marks around arguments. An unknown key gives the key; a bad catalogue entry is skipped; a bad language tag falls back to the undetermined one. The real catalogues are `crates/twake-i18n/locales/{en,fr}.ftl` (embedded with `include_str!`), keys named in `docs/dev/ui-screens-api-sketch.md` section 1; `Locale::bundled(lang, utc_offset_secs)` picks `fr*`, else English. Licences MIT/Apache-2.0, pure Rust, no `tokio`; `cargo xtask check-deps` accepts them.
- Product choices the specs left open: runs of messages group within 5 minutes (`GROUP_GAP_MS`); "this week" is a rolling six days before today; the 12 hour clock is supported (`HourCycle`); a read receipt on an event not in the list, and a reply whose target is not loaded, are out of scope (no read mark, no quote).
- Consequences: a locale detected from the OS and the web `*.json` conversion (S9) come later; the key list is the one of the sketch only.
- Risk: the web strings may need ICU features Fluent lacks (S9); the grapheme cut of the avatar initials is approximate (combining marks and joiners, no UAX 29 crate).
