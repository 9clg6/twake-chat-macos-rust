## Acceptance criteria (from e2e test bodies)

### e2eA: Spaces / channels / members / invitations

- [chat.e2e.ts] Given the room list When `create-room` > `create-space` > name > `create-submit` Then a `space-landing` card shows with a `space-channel` "General" (30 s); clicking it opens heading level 1 "General" with `composer-input` visible. A new channel via `space-create-channel` + name opens heading "Chan <stamp>"; its info shows the name.
- [chat.e2e.ts] Given channel info When `invite-member` pressed Then `add-member-option` contacts are listed with names before anything is typed; search placeholder "Search contacts"; typing "bob" and picking him + `add-members-submit` shows member `member` bob with text "Invited"; after Bob joins and writes, his message shows; the user's reply reaches Bob (channel in the clear, D17).
- [chat.e2e.ts] Given an invitation to a room on the own server Then it is joined at once: a room row appears, no `invite` element; room info lists the name; `leave-room` + `confirm` removes the row (30 s).
- [chat.e2e.ts] Given a session ended on the server Then within 60 s `sign-in` is shown and an alert contains "session has ended".

### e2eA: Search

- [chat.e2e.ts] Given `header-search` clicked Then the info panel opens on search with `room-search` focused; only the field at first (no `search-author`); Enter searches without reload; "COFFEE" finds "Who wants coffee?" case-insensitive; URL gains `event=`; changing the words clears `search-results` at once (#694); `search-advanced` absent; no match shows `search-empty` and `event=` leaves the URL.
- [chat.e2e.ts] Given search index in IndexedDB (name starting `twake-chat-search:`, store `messages`) Then records hold `roomId` but never the message text in clear (D21).
- [chat.e2e.ts] Given a clear room with a message 80 messages back When searching "owner" Then results contain it without "Search older" and no `search-empty` (#881). Given an encrypted room: `search-empty` and `search-incomplete` show first; `search-older` then finds it (60 s).

### e2eA: Direct messages

- [direct.e2e.ts] Given /new/direct Then `create-submit` is disabled; contacts (`create-person-option`) are listed before typing; typing "bo" shows bob with the typed letters in bold (`highlight` text matches /^bo$/i); picking sets aria-checked "true" and enables `create-submit`; pressing it removes the search and shows `composer-input`; the active `room-row` has no `room-kind-badge` (D187).
- [direct.e2e.ts] Given the create hub (`create-room`, `create-search` "bo", `create-contact` bob) When starting with bob twice Then the same URL and the same room-row count (no duplicate); `create-hub` closes.
- [direct.e2e.ts] Given a direct room Then room info shows `info-video` and no `info-message`, no `leave-room`, no `delete-chat`; header More has no `menu-delete-chat`; the row menu (`room-row-menu`) has `row-delete-chat` with text "Delete chat" and no `row-leave-room` (D225, workshop 2.4).
- [direct.e2e.ts] Given "Delete chat" confirmed (`confirm`) Then the row disappears (30 s); reopening the room URL shows a composer and header More offers `menu-block` (still a direct chat, #753).
- [direct.e2e.ts] Given a direct room Then the other person's message shows no `message-author`; in a group each message shows `message-author`.
- [direct.e2e.ts] Given a direct room, Bob read my message Then `seen-by` (avatar) shows under it; the message menu has `message-copy-link` but no `message-seen` row (D501).
- [direct.e2e.ts] Given a new direct chat with only room lines (e.g. "Alice created the conversation", "… joined") Then `room-line`s show first and `empty-conversation` card follows them in the DOM and does not overlap any.
