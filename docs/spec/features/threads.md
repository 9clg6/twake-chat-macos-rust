## Acceptance criteria (from e2e test bodies)

### e2eA: Threads

- [chat.e2e.ts] Given a root with replies Then `thread-card` under the root shows no title (root is just above it).
- [chat.e2e.ts] Given a thread card When clicked Then `thread-panel` shows the root and replies; sending in the panel's composer adds the reply; react (👍 button in message menu) shows `reaction` "👍" and `reaction-avatars` (face of reactor stands for count while few); edit via `message-edit` and send shows "(edited)" and the edit never appears as "* <text>" message nor on the card.
- [chat.e2e.ts] Given an image attached in the thread composer Then `composer-attachment` tile shows; its "Remove photo.png" button hides it with nothing sent; sent image appears as `image-preview` in the thread panel, not in the main timeline; `upload-progress` is gone after.

### e2eC: Threads

- [threads] Given a message without thread When "…" (`message-more`) > `message-start-thread` clicked Then `thread-panel` contains the root and `composer-input` in it is focused (D509); closed without reply: panel gone, no `thread-card`, no `thread-row`.
- [threads] Given the thread composer When ":smi" typed Then `emoji-suggestions` is visible; sending a reply shows it in the panel; the message then has a `thread-card`, `thread-row` count stays 0 (not in room list); the menu then has `message-copy-link` and no `message-start-thread`; the card reopens the panel.
- [threads] Given alice takes part in a thread of bob's root When bob replies Then it shows live in the open window, a thread receipt for that reply with thread id = root is sent within 15 s; after close, a new reply in her thread makes `unread-badge` text "1" (only her threads count: one, not two); the card contains "1 unread message"; opening the card reads it (receipt within 30 s, badge gone, kept after reload).
- [thread-window] Given a thread opens Then it is `role=dialog` named "Thread" with `data-testid=thread-panel` over the room (D3), room composer still visible; "Minimize the thread" sets `data-minimized="true"` and hides its `timeline`; "Restore the thread" shows replies; "Close" removes it and focus returns to the root message in the conversation.
- [thread-window] Given the window is open and the user opens another room Then it stays, answers in its own thread (the reply is not in the other room's timeline).
- [thread-window] Given "Expand the thread" (D406) Then the dialog count is 0 and `main` contains the replies and one `composer`, no "Minimize the thread" button; sending works; "Shrink the thread" returns to the window (2 composers on page); expanded then another room opened returns it to its window.
- [thread-window] Given two threads opened from two rooms (D309) Then 2 `thread-panel` are open side by side; minimizing one leaves the other `data-minimized="false"`; closing the second leaves 1.
- [thread-window] Given a video sent in a thread window and `video-play` clicked Then `image-viewer` covers the whole viewport width (equals window.innerWidth, wider than the window) and plays; "Close" returns to the thread (not minimized, reply still visible).
- [thread-window] Given the thread window open or minimized, and the composer growing to 6 lines Then the room's `composer-send` is still the topmost element at its centre.
- [thread-window] Given a 360 x 732 viewport and a minimized thread Then the tab lies above the composer (tab bottom <= composer top + 1).
- [thread-follow] Given an unfollowed thread (D60) Then it is not in `nav-activity` (`activity-thread` count 0); menu `thread-menu` > menuitem "Follow the thread" adds it to Activity; then the menu shows "Unfollow the thread"; "Mute the thread" then shows "Unmute the thread" and writes a push rule containing `app.twake.chat.thread.`; "Unfollow the thread" removes it from Activity.
- [thread-resolved] Given a thread (D56) When `thread-menu` > "Mark as resolved" Then `thread-resolved` (check) shows in the panel and on the `activity-thread` card (activity shows news only, never the user's own last reply, #709); "Reopen the thread" removes it.
- [thread-pinned-bar] Given an expanded thread (#805) Then `pinned-banner` shows only pins of that thread (contains "the answer", not "in the room"); not shown in the window nor minimized; `pinned-list` lists 1 `pinned-list-item`; clicking the banner highlights the message (`data-highlighted="true"`); a pinned message shows `message-pin-mark`; unpinning removes the banner.
- [read-on-screen] Given a followed thread far up with a new reply Then `unread-thread` banner shows (no receipt yet); `unread-thread-open` opens the panel and sends the thread receipt; banner gone.
