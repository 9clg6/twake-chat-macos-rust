## Acceptance criteria (from e2e test bodies)

### e2eA: Attachments

- [chat.e2e.ts] Given a file chosen Then composer shows `composer-attachment` tile with the file name ("photo.png") and an image; nothing leaves until send; caption "Our new office" becomes the image alt and message text.
- [chat.e2e.ts] Given image sent Then `image-preview` image shown at its own size (64 x 48); click opens `image-viewer` with img named by caption, a "Download photo.png" label control and "Close"; viewer dialog covers the whole viewport (left 0, top 0, width=innerWidth, height=innerHeight; D227); image whole and centred (±1 px) in the area under the header; viewer `data-theme="dark"` in either scheme (#576).
- [chat.e2e.ts] Given video sent Then tile `video-preview` has `video-play` and `video-duration` "0:01" (1.2 s clip); zero `<video>` elements in the message (never autoplays, D366); `upload-progress` hidden; play opens viewer with video 64x48, muted false, loop false, controls true; media tab (`info-tab-media`) shows button "clip.mp4" and a `media-tile` video with a decoded first frame.
- [chat.e2e.ts] Given a video uploading (D322) Then `outgoing-attachment` (data-kind="video") shows its first frame under a ring labelled "Sending the file…"; `outgoing-cancel` removes the bubble and no message is sent; sending again yields exactly 1 `video-preview`.
- [chat.e2e.ts] Given the video viewer When `video-viewer-compact` pressed Then viewer hides and `video-mini` corner player shows continuing from >= 0.5 s, its right edge within 40 px of the viewport right edge (D394).

### e2eC: Voice messages

- [voice-message] Given an empty composer Then `composer-voice` (microphone) shows and `composer-send` count is 0; once text is typed the voice button is gone and send is there; emptied, voice is back.
- [voice-message] Given `composer-voice` clicked Then `voice-recorder` shows; `voice-cancel` removes it and sends nothing; recording 2 s shows `voice-elapsed` containing "0:0"; `voice-send` has aria-label "Send".
- [voice-message] Given sent Then `voice-message` has one `slider` (waveform), `voice-play` toggles aria-label to "Pause"; server content: `msgtype` `m.audio`, `org.matrix.msc3245.voice` equals `{}`, `org.matrix.msc1767.audio` with `duration` > 1000 and an array `waveform`; room row `room-preview` text is "Voice message" (D54).
- [voice-message] Given an encrypted room Then the voice message uploads encrypted (server has `ciphertext`), the player works and shows "Pause" after play.
- [voice-message] Given the microphone is missing (NotFoundError) Then an `alert` mentioning microphone has text matching "No microphone was found" and no recorder; when refused (NotAllowedError) text matches "The microphone was refused".

### e2eC: Media, attachments

- [attachment-caption] Given text typed then a photo attached Then no dialog (`attachment-dialog` count 0), the photo waits as `composer-attachment` above the field, text stays; nothing sent before Send; one message results (`m.image`, body = text, filename photo.png), composer empty.
- [attachment-caption] Given a waiting photo tile Then it opens alone in `image-viewer` (button "Open photo.png"; no next/previous), "Close" closes; the cross "Remove photo.png" removes it, field focused, nothing sent.
- [attachment-caption] Given several files Then several tiles, one can be removed, more added; Send makes one album (`image-album`) with the text on the last one as caption.
- [attachment-caption] Given a non-picture (notes.txt) Then the tile shows the icon and "notes.txt", no img, no "Open notes.txt" button; sent as `m.file` with filename, no caption.
- [attachment-caption] Given "@bo" in the caption Then `mention-suggestion` contains "bob"; Enter picks (value "bob "), photo stays; sent has `m.mentions` user_ids `["@bob:localhost"]` and a matrix.to link; drawn as a link named "bob".
- [attachment-caption] Given the author edits a caption via `message-edit` Then composer has the old caption; after save the message contains "(edited)" and keeps `image-preview`.
- [attachment-caption] Given a long caption Then Shift+Enter makes a new line and grows the field; Enter sends; body `First line <stamp>\nSecond line`.
- [attachment-caption] Given an SVG (with script) Then it is drawn from a PNG, script never runs, no "pwned".
- [attachment-reply] Given a reply in progress and a photo Then `composer-context` stays while the photo waits; after sending the image has `message-quote` with the quoted text and the context is hidden; after send or remove the field is focused.
- [attachment-thumbnail] Given a 1600 x 1200 photo Then `info.thumbnail_info` is `{ w: 800, h: 600, mimetype: image/jpeg }` and `thumbnail_url` is a string.
- [attachment-placeholder-type] Given `m.file` typed "file/video" (Flutter client, D557) Then `video-preview` shows, and `video-play` plays it in `image-viewer` (no error, readyState >= 2). A file chip has margin-top 8px with a caption, 0px without.
- [image-album] Given 3 images picked at once Then 3 `composer-attachment`; one caption "Our trip"; one `image-album` with 3 `album-tile`, caption inside; clicking opens a dialog; a tile keeps its message menu (`message-delete`, `message-start-thread`), the first quick reaction adds one `reaction`; right click on the tile opens the same menu (D89).
- [image-album] Given two separate sends of 2 photos within the minute Then 2 albums, 2 tiles each (#567).
- [image-gallery] Given two images with captions "First photo", "Second photo" Then the viewer from the timeline shows "2 of 2", Next disabled, "Previous image" gives "1 of 2" (Previous then disabled); ArrowLeft/ArrowRight navigate; Escape closes; from the Media tab (`info-tab-media`, newest first) the viewer opens at "2 of 2"; Close via label "Close".
- [album-tile-hover] Given an album of 2 tiles Then the hover row `message-hover-reactions` stays within album bounds (x >= start - 1, right <= end + 1) and lines up within 12 px of the left edge of the left tile / right edge of the right tile; the Reply/"…" pill is wider than tall with radius in px >= height/2 - 1 (2026-11-09).
- [album-tile-hover] Given the hover row of the left tile Then clicking "React with 😮" reacts on the left image only (right has 0 reactions); after, hovering the right tile hides the left row (opacity 0 within 5 s) and "React with 👍" goes to the right image only.
- [album-tile-hover] Given hovering an image Then the tooltip "Open a1.png" / "Open a2.png" never overlaps the hover row.
- [album-tile-hover] Given a 390 x 844 viewport Then an album of someone else stays inside its bubble, two equal columns, square images (|w-h| <= 1), each <= 158 px, no horizontal scroll.
- [video-mov] Given a .mov with caption Then the composer tile shows a video frame (videoWidth > 0); sent as `m.video`, body "screen-recording.mov", mimetype video/quicktime; `video-preview` has `video-play`; click opens `image-viewer` and plays.

- [video-mov] Given a video in the timeline Then `video-play` and `video-duration` show and there is no `<video>` element (0) until play is clicked (downloaded when played, not when scrolled).
