## Acceptance criteria (from e2e test bodies)

### e2eA: Appearance

- [chat.e2e.ts] Given settings > appearance (`open-appearance`) > `theme-dark` Then after reload the round composer button `composer-voice` has an icon/background contrast ratio checked against WCAG (#450; see threshold below).

### e2eA: Settings: theme, language, session, verification

- [chat.e2e.ts] Given the dark composer (theme-dark) Then icon/background contrast of `composer-voice` >= 4.5 (WCAG formula, #450).
- [chat.e2e.ts] Given settings > appearance > `theme-dark` Then `<html data-theme="dark">`, kept on reload; `theme-system` restores.
- [chat.e2e.ts] Given common settings enabled in well-known (`app.twake.chat.common_settings` {enabled, application_url '.../settings/{username}'}) and ToM user_info theme "dark" Then `data-theme="dark"`; settings head `profile-settings` has link "Edit in Twake settings" -> http://127.0.0.1:3000/settings/alice; appearance shows `theme-shared`, `theme-dark` checked, `theme-light` disabled, link "Change it in the Twake settings"; when theme becomes "light" and the tab becomes visible again, `theme-light` is checked and `data-theme="light"` without reload (D68, D38).
- [chat.e2e.ts] Given common-settings language "fr-FR" Then `<html lang="fr">`; `language-shared` shown, `language` select disabled, link "Le modifier dans les paramètres Twake" -> same settings URL (D67).
- [chat.e2e.ts] Given a reload When the app reopens Then the list kept by the last session shows a `room-row` within 3 s and `sign-in` hidden.
- [chat.e2e.ts] Given the device has no recovery key from ToM (500) Then `security-banner` has a button; `verify-with-device` opens `verification-dialog` containing "recovery key" (30 s) while another verified device receives the request.
- [chat.e2e.ts] Given another device of the user requests verification Then `verification-accept`; `verification-qr` shows (aria-label "QR code to scan with the other device", carries `data-qr`); after the other device scans, `verification-scan-ok`; dialog contains "Device verified"; `verification-done` check visible.
- [chat.e2e.ts] Given camera denied When `verification-scan` pressed Then `camera-error` alert contains "The camera is not available"; the QR stays and verification can still complete.

### e2eA: Display / personalization / offline (display.e2e.ts)

- [display.e2e.ts] Given settings > appearance (`open-appearance`) Then `clock-24h`, `clock-auto`, `density-compact`/`density-comfortable`, `order-sections`/`order-recent` choices exist; compact makes the settings row (`open-appearance`) shorter than comfortable but still >= 24 px (D328); `clock-24h` stays checked.
- [display.e2e.ts] Given order "sections" Then the room list groups by kind under titles incl. "Groups" (exact text) (D190).
- [display.e2e.ts] Given compact density and a read room Then `room-kind-badge` on the 32 px avatar is 14 px wide (an unread count takes its place, 2026-11-06).
- [display.e2e.ts] Given the 24-hour clock Then a message aria-label ends /, \d{2}:\d{2}$/ (e.g. "bob, 14:32", no AM/PM) and a read room's `room-time` matches /^\d{2}:\d{2}$/; an unread row hides its time while its count shows.
- [display.e2e.ts] Given the info panel beside the conversation (compact too) Then the bottom of `pane-header` of the panel equals the bottom of the main pane header (same line).
- [display.e2e.ts] Given the first visit of a browser (D261) Then `personalize-dialog` shows: `personalize-step` "Step 1 of 3" (no `personalize-back`); 2 `personalize-preview` cards (compact row height < comfortable row height); clicking a card's preview checks `personalize-compact`; `personalize-next` -> "Step 2 of 3" (list order: 2 previews; "recent" preview has no "Groups" title, "sections" preview shows "Groups"); `personalize-sections` checks; `personalize-back` returns with compact still checked; "Step 3 of 3" has no `personalize-next`; `personalize-done` closes it; it does not return on reload; list then shows a "New messages" section (rooms with new messages first) containing the room.
- [display.e2e.ts] Given settings > appearance > Personalization Then `wallpaper-none` sets `<html data-wallpaper="none">`, `toggle-grayscale` sets `data-grayscale`, `toggle-do_not_disturb` is checked by default; `text-size-large` scales the whole app (heading "Text size" > 1.1x, bottom-bar caption font > 1.1x), `text-size-normal` restores exactly; `<html data-text-size="large">`.
- [display.e2e.ts] Given `toggle-high_contrast` Then `<html data-contrast="more">` (default absent = off), kept after reload, axe holds.
- [display.e2e.ts] Given settings > notifications Then `notification-text` is checked by default (message text shown in notifications).
- [display.e2e.ts] Given a profile (button /^View the profile of stranger/) When `profile-ignore` + `confirm` Then their messages vanish from the timeline and the button reads "Unblock user"; pressing again restores them. An ignored person leaves the room-list `room-preview` and `unread-badge` (30 s), and their reactions leave the messages.
- [display.e2e.ts] Given `align-left` and `text-size-large` Then all messages (own too) sit left of the timeline centre; by default own messages (`align-own-right`) sit right of the centre; a context-menu on a room row opens its menu (`mark-unread`) at the pointer, offset within 12 px of the normal-size offset with large text.
- [display.e2e.ts] Given the browser goes offline Then `offline-banner` shows (its parent animates 0.2s, D34), a status live region contains "offline"; back online hides it. A message sent offline shows in the timeline within 5 s.
