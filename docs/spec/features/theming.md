## Acceptance criteria (from e2e test bodies)

### e2eA: Motion

- [chat.e2e.ts] Given the info panel opens Then it plays a 0.2s arrival animation; composer round icon (mic<->arrow swap on first letter / emptied) 0.1s; reply banner `composer-context` 0.125s; `message-selection-bar` 0.15s; `message` and `room-row` have no animation (none).

### e2eA: Keyboard

- [keyboard.e2e.ts] Given the top of the page Then within 2 Tab stops the focus is `skip-to-conversation`; Tab reaches the list search INPUT; typing the name filters; Tab (<=20) to the room row; Enter opens it and focuses the H1 with the room name.
- [keyboard.e2e.ts] Given `skip-to-conversation` + Enter Then focus is on the timeline (role "log"); ArrowUp moves focus to a message (role "article") whose aria-label contains the message text.
- [keyboard.e2e.ts] Given a focused message When Tab (<=6) Then the control labelled "Message actions" is reached; Enter opens a menu named "Message actions" focused on "React with ❤️"; ArrowRight -> "React with 👍"; ArrowLeft back; Enter reacts (`reaction` contains "❤️"); one Tab leaves the toolbar to a control whose label is not React/More/Reply/Message actions.
- [keyboard.e2e.ts] Given F6 Then focus moves between landmarks (app bar region `app-bar-region`, nav, main, complementary); within 5 presses reaches MAIN; Tab reaches `composer-input`; typing and Enter sends.
- [keyboard.e2e.ts] Given an icon button (e.g. "New conversation") When focused by Tab Then a tooltip (role tooltip, text "New conversation") shows (WCAG 1.4.13), Escape hides it without moving focus; on hover too; no native `title` attribute.
- [keyboard.e2e.ts] Given the reactions "more" picker or the composer emoji button ("Insert an emoji") When opened Then focus is on the picker's search INPUT; Escape closes. Given own message deleted Then focus lands on another message (role article) and `notice-deleted` shows.

### e2eA: Responsive layout

- [responsive.e2e.ts] Given a 320 or 640 px viewport (700 high; WCAG 1.4.10 reflow) Then one pane at a time with no horizontal scroll: list visible, opening a room hides `room-list` and shows the timeline; `pane-title-button` shows `info-panel` at once (never empty) and hides the timeline; "Hide room info" returns to timeline; `back-to-list` returns to the list.
- [responsive.e2e.ts] Given widths 320, 390, 768, 769, 1280 (height 800) Then room list, conversation and info each have no layout defect (overflow across, overlaps, text cut without ellipsis, controls out of reach). 769 px is the info-pane breakpoint (D220).
- [responsive.e2e.ts] Given WCAG 1.4.12 text spacing (line-height 1.5, letter-spacing 0.12em, word-spacing 0.16em, paragraph margin 2em) at 1280 and 320 px Then nothing is cut off or overlaps.
- [responsive.e2e.ts] Given a message menu closed with Escape then viewport 1440 -> 390 Then no tooltip "Message actions" remains; `composer-attach` ("+") opens a menu containing `composer-poll`.
- [responsive.e2e.ts] Given a conversation scrolled to bottom at 390 px When window widens to 1280x720 Then still < 16 px from bottom and no `jump-to-latest` (#892).
- [responsive.e2e.ts] Given 390 px Then `header-search` is absent, `header-more` menu has `menu-search` which focuses `room-search`; at 1280 px `header-search` is visible (D473).

### e2eA: App frame (D29)

- [app-frame.e2e.ts] Given signed in Then a banner contains an image named "Twake Chat"; navigation named "Sections" and navigation named "Conversations" are visible; `nav-chat` has aria-current "page"; "Contacts" button in Sections is enabled.
- [app-frame.e2e.ts] Given `app-bar-help` Then a menu with `help-contact-support`, `help-shortcuts` (opens `shortcuts-list` containing "F6"), `help-about` (opens `about-version` containing "Version") (D379); `app-bar-apps` is disabled.
- [app-frame.e2e.ts] Given `open-settings` Then `open-notifications` visible and `open-settings` aria-current "page"; `nav-chat` goes back (D32).
- [app-frame.e2e.ts] Given a room open Then the page never scrolls (documentElement.scrollHeight - innerHeight = 0); at 1280x480 the side pane holding `info-panel` scrolls itself (scrollTop > 0), page overflow 0, `overscroll-behavior-y: none` on the html element.
- [app-frame.e2e.ts] Given `app-bar-account` Then `account-sign-out` visible; `open-my-profile` shows the complementary pane containing "@alice:localhost".
- [app-frame.e2e.ts] Given 360x700 Then `room-view-more` (filters arrow) lies fully inside 0..360 px.
- [app-frame.e2e.ts] Given 360 px with the room list Then banner and `nav-chat` are visible; with a conversation open `nav-chat` hidden, banner still visible; `back-to-list` goes to the list; settings on phone shows sections first (`open-about` visible, `settings-notifications` absent), `open-about` shows `app-version` and hides `open-about`; `back-to-list` returns to sections (D32).
- [app-frame.e2e.ts] Given a Twake platform (D64) Then `twake-bar` has data-status "ready", exchange request contains `"exchange_type":"app"`, exactly one banner, no `app-bar-help`, bar has image "Twake Chat" and link "Home" to the platform home; bottom bar (`nav-chat`) stays; status is set from settings `profile-set-status` -> `status-field` (Escape closes it); `twake-bar-user-button` > `twake-bar-logout` signs out (`sign-in` visible).
